# ServerTimeClicker

지정한 웹사이트의 **서버 시간**에 맞춰, 화면의 여러 좌표를 정해진 순서대로 클릭하는 데스크톱 앱입니다.

예약·티켓팅처럼 "서버가 정한 시각"에 동작해야 하는 상황을 위해 만들었습니다.

## 왜 대상 사이트의 시간에 맞추는가

예약이 열렸는지는 **그 사이트의 서버가 자기 시계로** 판단합니다. 그래서 기준 시계를 잘못 고르면 아무리 정확해도 소용이 없습니다.

실제로 측정한 예입니다.

| 사이트 | 내 PC 시간과의 오차 |
| --- | --- |
| map.naver.com | +19 ~ +73 ms |
| www.google.com | +57 ms |
| zeroworldkorea.com | **-1,020 ms** |

네이버와 구글이 서로 수십 ms 안에서 일치하므로 PC 시계는 정확합니다. 그런데 어떤 사이트는 자체 서버 시계가 1초쯤 느립니다. 이 사이트를 네이버 기준 `12:30:00.000`에 클릭하면, 서버는 아직 `12:29:58.98`이라고 여겨 "아직 열리지 않았다"며 거절합니다.

그래서 이 앱은 **클릭할 대상 사이트에 직접 동기화합니다.** 오차가 -1초로 나오는 것은 버그가 아니라 그 서버가 실제로 느리다는 뜻이고, 그 값을 그대로 써야 맞습니다.

시간은 HTTP 응답의 `Date` 헤더에서 읽습니다. 헤더는 초 단위라, 값이 바뀌는 순간(초 경계)을 포착해 밀리초까지 좁힙니다. 앱이 켜져 있는 동안 8초마다 다시 맞춰 시계 드리프트를 따라갑니다.

## 요구 사항

- **JDK 21** (`JAVA_HOME` 설정 필요)
- Windows (전역 단축키와 클릭에 사용)

Maven은 설치하지 않아도 됩니다. 저장소에 포함된 래퍼가 알아서 받아 씁니다.

## 실행

```bash
./mvnw javafx:run      # macOS/Linux
.\mvnw.cmd javafx:run  # Windows
```

## 사용법

1. **기준 사이트** — 클릭할 페이지의 주소를 넣고 `적용`을 누릅니다. `https://`는 생략해도 됩니다. 적용 시 그 사이트가 실제로 시간을 주는지 즉시 확인하고, 실패하면 이전 설정을 유지합니다. 인증서 체인이 불완전한 사이트라 적용이 막히면, 신뢰할 수 있는 사이트에 한해 `인증서 검증 완화`를 켜고 다시 시도할 수 있습니다(개별 연결에만 적용되며 JVM 기본 신뢰 설정은 건드리지 않습니다).
2. **좌표 지정** — 클릭할 위치에 마우스를 올리고 `Ctrl + F1`을 누릅니다. 누를 때마다 목록에 순서대로 쌓이며, 위에서부터 차례로 클릭합니다. `마지막 취소`로 하나씩, `좌표 초기화`로 전부 지웁니다.
3. **클릭 간격** — 좌표 사이의 간격(ms)입니다. 기본 300ms. 클릭마다 페이지가 반응해야 하므로 너무 짧으면 아직 그려지지 않은 자리를 클릭하게 됩니다.
4. **목표 시각** — `HH:mm:ss`로 입력하거나 `다음 30분 자동 입력`을 씁니다. 이미 지난 시각은 다음 날로 잡힙니다.
5. **예약 시작** — 목표 5초 전에 정밀 재동기화한 뒤 대기합니다.

시계가 **회색**이면 현재 기준 사이트로 동기화되지 않은 상태라, 표시된 시간은 서버 시간이 아닙니다. 이때는 예약 시작이 막힙니다. **청록색**이면 동기화된 상태입니다.

### 클릭 타이밍

첫 클릭은 목표 시각 + 안전 지연에 발생합니다. 안전 지연은 RTT에 여유를 더해 45~160ms 사이에서 자동으로 정해지며, 요청이 서버에 **일찍 도착해 거절당하는 것**을 막기 위한 값입니다.

이후 클릭은 직전 클릭이 아니라 목표 시각을 기준으로 계산하므로 오차가 누적되지 않습니다. 좌표 4개 / 간격 300ms 실측:

```
클릭 1/4  목표 대비  +91 ms
클릭 2/4  목표 대비 +391 ms
클릭 3/4  목표 대비 +692 ms
클릭 4/4  목표 대비 +991 ms
```

## 설치파일 만들기

JDK가 없는 PC에서도 쓸 수 있는 exe 설치파일을 만듭니다.

```bash
.\mvnw.cmd clean package -Pinstaller
```

결과물은 `target/dist`에 생깁니다. [WiX Toolset v3](https://wixtoolset.org/)가 필요하며, 경로가 다르면 `-Dwix.bin.dir=...`로 지정하세요.

## 한계

- **`Date` 헤더를 주지 않는 사이트**는 쓸 수 없습니다. 이 경우 적용 단계에서 그렇게 안내합니다. HEAD를 막는 서버는 GET으로, 봇 차단은 브라우저 User-Agent로 우회하며, 4xx/5xx 응답이라도 `Date`가 있으면 사용합니다.
- **CDN이 `Date`를 캐시**하면 값이 실제보다 뒤처질 수 있습니다. 앱은 이를 구분하지 못하므로, 오차가 의심스러우면 응답 헤더(`Age`, `X-Cache` 등)를 직접 확인하세요.
- 좌표는 **화면 절대 좌표**입니다. 창을 옮기거나 해상도·배율을 바꾸면 다시 지정해야 합니다.

## 유래

이 프로젝트는 두 선행 프로젝트를 합쳐 만들었습니다. 이력은 NaverMapClicker를 이어받고, TimeSyncClicker의 고유 기능을 이식했습니다.

- **NaverMapClicker** (직계 조상, 아카이브됨): 서버 시간 동기화·좌표 시퀀스 클릭·설정 가능한 간격·배포 안정화(Launcher, VC 런타임 preload, 소프트웨어 렌더링 폴백)·jpackage 설치 프로파일
- **TimeSyncClicker** (아카이브됨): 인증서 검증 완화(trust-all 소켓 팩토리)·인증서 체인 오류 감지·정밀 동기화 구간 백그라운드 동기화 일시정지·press-hold 클릭 타이밍

두 저장소는 읽기 전용(archived)으로 보존되며, 이후 개발은 이 저장소에서만 이어집니다.
